## 0. Foundational design decisions (read first)

These choices hold up everything else. If one of them falls, the design changes.

| Decision | Why |
|---|---|
| **Every signal is a 2D vector.** No 3D or higher in the base game. | 2D is the smallest space where rotation, shear, non-orthogonality, and vector-vs-readout duality all exist. 3D adds cost to readability and almost nothing to the concepts. |
| **Signals are sums of tagged components** (friendly = cyan, hostile = red, noise = grey, unknown = white). The simulation is linear, so tags propagate independently. | Players need to *see* what is theirs and what is the enemy's. The tags are a deliberate readability cheat. Real signals don't come labelled, and later levels take labels away (white "unknown" components). |
| **Nodes apply 2×2 linear maps (Jacobians), then a radial saturation clip.** | Linear maps make the chain rule exact: the gain along a chain is the product of the local Jacobians. The clip is the only nonlinearity, and it's enough to create norm drama and "deaf" nodes (§6.5). |
| **Readouts are first-class objects, distinct from arrows.** A readout is a covector. It is drawn as a **grating** (a stack of parallel level lines). | This is the duality revelation (§6.6). It only works if readouts had their own visual identity from the start, even while the game draws them as arrows in honest spaces. |
| **The clock is discrete.** Each tick, packets advance one edge. | The game reads as a pipeline the player can watch. Each consequence has a visible travel time. |
| **The Core doesn't care about tags.** It applies its readouts to the total vector. | A friendly packet bent into the threat channel *hurts you*. That keeps tags from trivialising the geometry. |

## 1. Game pitch

**NULLBASIS: Chainwarden Protocol** is a real-time tactical puzzle game. You play
a Chainwarden defending a living computational network from signals that can't
be shot down, only *out-thought*. Every encounter is a luminous graph of nodes
that pass, stretch, rotate, mix, and amplify signal packets toward a Core you
must keep fed and safe. Hostile signals hide inside the chain itself. Some lie to
your instruments by bending the coordinate grid. Others really do deform the
signal. Some appear only in the echoes that ripple *backward* through the
network. You win by predicting how a change *here* will arrive *there*, choosing
the one intervention that unravels a threat across the whole chain, and watching
the consequences of your choices, good and bad, flow downstream in real time.
It's a game about seeing the hidden structure of a machine. Somewhere around the
third act you realise you've been thinking in chain rules, dual spaces, and
metrics all along.

## 2. Central player fantasy

> *I can see the machine's hidden structure. I know where a disturbance will
> land before it lands. I don't fight the threat where it hurts me. I reach back
> up the chain and unmake it where it starts.*

The fantasy isn't about power. It's about **foresight and leverage**: the
pleasure of one small, well-placed intervention whose effect grows as it
propagates. The power fantasy grows with understanding, not with stats. A
veteran Chainwarden doesn't have stronger tools. They have tools they can trust,
because they know when the instruments are lying.

## 3. Core gameplay loop (5 steps)

1. **Observe.** Watch packets flow for a tick or two. Note where red grows, where
   arrows bend, which nodes behave strangely.
2. **Hypothesise.** Form a causal claim: "N2 amplifies vertical. N1 is lying
   about angles. The Leech at Intake is the source."
3. **Probe (optional, costs Heat).** Confirm cheaply with a Lens, a Scan, a
   Ping, or a ghost preview. Or skip it and bank the Insight bonus.
4. **Intervene (costs Bandwidth).** Install a filter, clamp, alignment, or strike
   at a chosen node and tick.
5. **Watch it propagate.** The effect travels the chain over the next ticks.
   Success and failure are both readable as they happen, so the next hypothesis
   starts with better information. Loop.

The loop runs inside a **combat clock** (§14), and each pass through it is
usually 1–3 ticks long.

## 4. Underlying puzzle-state model

### 4.1 World state (authoritative simulation)

```
Encounter
├── tick: int,  period: seconds,  frozen: bool
├── resources: { bandwidth, heat, freeze }       (§6.0)
├── nodes[]: Node
├── edges[]: Edge              (directed, latency = 1 tick unless stated)
├── emitters[]: Emitter        (friendly or hostile sources)
├── threats[]: Threat          (enemy behaviours attached to nodes/edges/emitters)
├── packets_in_flight[]: Packet
└── win/lose conditions, score accumulators
```

**Node** (all fields in TRUE coordinates; display is derived):

| Field | Type | Meaning |
|---|---|---|
| `J` | 2×2 | Physical local transform (the Jacobian). Applied to everything entering. |
| `cap` | number | Saturation radius. If the true norm of the output exceeds `cap`, the output is clipped radially. |
| `integrity` | number | Node health. Loses 1 per tick spent saturated. At 0 the node is *broken*: it outputs zero. |
| `frame` | 2×2 orthogonal | Local port frame Q. Ports and installed filters are defined in this frame. |
| `display` | 2×2 | Map from true to displayed coordinates (A). Identity when honest. Corrupted by Shear Phantoms. |
| `G_true` | 2×2 SPD | True metric in true coordinates. Identity in the base game. Kept general for Interference Swarm levels. |
| `G_believed` | 2×2 SPD | The metric the node's instruments assume: `Aᵀ A` when `display = A` (they treat the screen as Euclidean). |
| `ports` | `free` \| `axis-locked` \| `none` | Where filters may be aimed. |
| `filter` | Filter? | At most one installed Projection Pulse (STRIP or KEEP) with aim `u` and readout `r`. |
| `clamp` | number? | Optional Norm Clamp radius κ. |
| `align` | `none` \| `honest` \| `spare(component)` | Dual Align state. |
| `readouts[]` | covector[] | Fixed readouts. Core nodes have Supply and Threat readouts. |
| `hidden` | set of field names | Which fields are hidden from the player (`J`, `display`, `threat`…). |

**Order of operations inside a node each tick:**
`input (sum of arriving packets) → J → saturation clip at cap → clamp κ → filter P → output to every outgoing edge`.

**Packet**: `{ components: [{tag, vector}], edge, eta }`. Components are tracked
separately, but the clip and the Core readouts act on the **sum**. When a clip
scales the sum, every component is scaled by the same factor.

**Emitter**: `{ node, tag, direction d (unit), strength s(t), hp }`. Each tick it
emits `s(t)·d` into its node.

### 4.2 Observable state (what the player sees)

- Per node: displayed output components (arrows in **display** coordinates on the
  node's local lattice), node glyph (transform type, unless `J` is hidden),
  saturation ring, integrity pips, installed filter/clamp/align glyphs.
- Per edge: packets in flight (forward chevrons), backward ripples (§6.5).
- Core: Supply meter, Threat meter, integrity.
- Global: clock ring, resources, and the Propagation Ledger (a scrolling log of
  per-tick events: "t5 N2 SATURATED, friendly −5%").

### 4.3 Hidden state (what the player must infer)

`J` on sealed nodes; `display ≠ I` (the Phantom draws a square lattice anyway);
`G_true`; Gradient Ghost perturbations; threat timers; untagged (white)
components. The design rule: **every hidden field must leave a footprint
somewhere the player can see without paying.** (Example: a lying display at N1
is betrayed by N2 showing a geometry N1's transform couldn't have produced. See
§10.3.)

## 5. Fundamental player action grammar

Every player action is a sentence:

> **VERB** at **NODE** (with **AIM** and/or **READOUT**) at **TICK**

| Verb class | Tools | Changes physics? | Changes knowledge? |
|---|---|---|---|
| **Perceive** | Metric Lens, Shear Scan, Ping (Backprop Strike mode), ghost preview | No | Yes |
| **Reframe** | Basis Rotate, Dual Align | No (representation/readout only) | Indirectly |
| **Shape** | Projection Pulse, Norm Clamp | Yes, forward | No |
| **Reach back** | Backprop Strike | Yes, at the sources | Yes (ripple shape) |
| **Buy time** | Chain Freeze | No | No (but gives time to think) |

Three grammatical rules make the game a chain-rule game rather than an
object-poking game:

1. **Effects are installed, not instant.** A filter at N1 affects every packet
   that passes N1 *from now on*. Its consequence is seen at the Core
   `(distance) ticks later`. Packets already in flight are unaffected.
2. **Location is leverage.** The same filter does different things at different
   nodes, because downstream Jacobians reshape what it lets through. Scoring
   rewards upstream leverage (§16).
3. **Aim and readout are separate arguments.** Early on the game fills in the
   readout automatically from the aim, and players never notice. The shear acts
   are where they come apart.

### 5.1 Mechanic cards (the six-question test)

Each core *system* (not just tool) must answer: **State / Observe / Act / Sim /
Feedback / Tradeoff.**

**Propagation**
- *State:* packets on edges; node Jacobians `J`; clip radii.
- *Observe:* arrows grow, shrink, turn, and flip as they pass nodes. Node glyphs
  (when unsealed) show the transform: a stretch glyph has two bars of different
  lengths, a rotation glyph is a swirl, an inverter is a hollow arrowhead.
- *Act:* any Shape verb at a node.
- *Sim:* `out = P(clamp(clip(J · in)))`, then copied to all outgoing edges. Joins
  sum their inputs.
- *Feedback:* the changed packet visibly travels on; the Ledger notes Core deltas
  when it arrives.
- *Tradeoff:* intervene upstream (high leverage, uncertain prediction) or
  downstream (cheap certainty, damage already incurred, saturation may already
  have destroyed friendly signal).

**Sensitivity**
- *State:* the product of Jacobians along each path (computed, never shown
  numerically by default).
- *Observe:* a small upstream wobble that grows into a big downstream swing. The
  optional ghost preview shows the downstream ghost of a hypothetical change.
- *Act:* choose *where* to intervene.
- *Sim:* chain rule. A change δ at node k arrives at the Core as `J_n … J_{k+1} δ`.
  Across parallel paths, the arrivals **sum with sign**.
- *Feedback:* the Core meter delta is shown on arrival, along with which path it
  came from (the path glows).
- *Tradeoff:* the loudest path is not always the most influential, and a path
  with negative gain may be *protecting* you (§8, L2).

**Coordinate integrity (representation vs physical)**
- *State:* `display` (A) and `J` per node.
- *Observe:* the node's arrows. The giveaway is **inconsistency between adjacent
  nodes**: a lie is local to the lying instrument, while a real deformation keeps
  propagating.
- *Act:* Lens or Scan to confirm, Dual Align to correct readouts, or route
  around the node.
- *Sim:* `display` never changes physics. It only changes what the node's
  instruments (and the default readout-from-aim conversion) believe.
- *Feedback:* a wrong assumption produces friendly fire or leaks (§12). A right
  one produces a clean Core.
- *Tradeoff:* diagnosing costs Heat and Insight. Guessing costs nothing until
  it's wrong.

**Duality (move vs read)**
- *State:* every filter has an aim `u` (vector) and a readout `r` (covector).
- *Observe:* by default, readouts are drawn as arrows. With Grating View or
  Lens, they're drawn as level-line gratings.
- *Act:* Dual Align sets `r` honestly, or independently of `u`.
- *Sim:* `P = I − u rᵀ / (rᵀ u)` (STRIP). Under a coordinate change `x' = A x`,
  aims transform as `u' = A u`, readouts as `r' = A⁻ᵀ r`. The game stores
  everything in true coordinates and converts on display.
- *Feedback:* the aim arrow and the grating visibly come apart on a sheared node.
- *Tradeoff:* HONEST needs a paid diagnosis. SPARE needs no diagnosis but costs
  more and amplifies anything you didn't account for (§6.6).

**Backward influence**
- *State:* adjoint edges (one per forward edge, reversed).
- *Observe:* magenta ripples travelling right-to-left on the adjoint rail, growing
  or shrinking as they pass nodes.
- *Act:* Backprop Strike or Ping from a chosen node and readout.
- *Sim:* `g_prev = Jᵀ g` through each node, including the clip's Jacobian and
  filters' `Pᵀ`. Damage at emitters = `|g · d|`.
- *Feedback:* source glyphs crack in proportion to damage; friendly emitters
  flash if they were hit.
- *Tradeoff:* strikes are expensive, don't touch packets already in flight, and
  are weakened ("deafened") by saturated or clamped nodes on the way.

## 6. Player tools

### 6.0 Resource economy

Three resources, each covering a different part of the player's work:

| Resource | Represents | Start / Cap | Regen | Spent by |
|---|---|---|---|---|
| **Bandwidth (BW)** | *Doing* | 10 / 12 | +1 per tick | Shape, Reframe, Reach-back verbs |
| **Heat** | *Knowing* | 0 / 100 | −10 per tick | Perceive verbs. At 100: **Overheat**, all Perceive verbs locked for 3 ticks, then Heat resets to 60 |
| **Freeze** | *Time* | 100 / 100 | +5 per tick | Chain Freeze, 25 per real-time second |

BW limits *how much you change*. Heat limits *how fast you can learn*. Freeze
limits *how long you can think*. No other spendable resources exist; Core and
node integrity are health, not currency.

**Ghost preview** (an assist, not one of the eight tools): hover a tool over a
node for 0.5 s to see the ghosted outputs of the next 2 downstream nodes as if the
tool were installed. Each committed preview costs **10 Heat** and counts against
Insight.

### 6.1 Metric Lens

| | |
|---|---|
| **Cost** | 30 Heat. Lasts 2 ticks on one node. |
| **State read** | `display`, `G_true`, `G_believed` of the target node. |
| **Shows** | An amber **true unit ellipse** drawn over the node's lattice, i.e. the set of displayed vectors whose *true* length is 1. A circle means the display's lengths and angles are honest; an ellipse means they're not. All readouts at the node are redrawn honestly as gratings. |
| **Enables** | Dual Align HONEST at this node, for the rest of the encounter. |
| **Limits** | It shows *how the display relates to the truth* at this node. It does **not** say whether the *signal* was deformed upstream (that's Shear Scan), and it doesn't solve anything. One node at a time. |
| **Tactical use** | Read true angles and lengths before a pulse. Spot a packet that looks short but is close to the clip radius. |
| **Tradeoff** | 30 Heat is a third of your Heat ceiling. Two Lenses and a Scan in one tick means Overheat. |
| **Math analogue** | Metric tensor `g`, drawn as its unit ball `{x : xᵀGx = 1}` in display coordinates. |

### 6.2 Basis Rotate

| | |
|---|---|
| **Cost** | 1 BW. Instant. |
| **State changed** | Node `frame` Q ← R(±45°)·Q, or a reflection across a port axis. |
| **Effect** | The node's port axes and displayed lattice rotate. **Signals don't change**: lengths, angles, dot products, and interference all stay the same. Vectors and readouts rotate *together*, because for orthogonal Q, `Q⁻ᵀ = Q`. |
| **Tactical use** | Line up an axis-locked port with a target component. Counter-rotate against a Basis Worm. Reorient a display so two components are easier to tell apart by eye. |
| **Gotcha** | **Installed filters live in the node frame.** Rotating after installing a filter rotates the filter's true aim. Basis Rotate is safe for geometry and unsafe for anything bolted to the old frame. |
| **Tradeoff** | Cheap, but every rotation can break an existing setup. |
| **Math analogue** | Orthonormal change of basis. The player learns that rotation changes the representation, not the geometry, and that this is the one regime where arrows and readouts behave alike. |

### 6.3 Shear Scan

| | |
|---|---|
| **Cost** | 25 Heat. Takes **1 tick**: the result arrives at the next tick boundary. |
| **Requirement** | **Rank-2 traffic.** During the scan tick, at least two non-parallel components must pass the node. Otherwise the result is INCONCLUSIVE, and a Mk II Phantom forges a CLEAN instead. |
| **Mechanism** | Compares the Gram matrix (all pairwise dot products) of the passing components in the *upstream node's honest frame* with (a) what this node *reports* (shows a display lie) and (b) what this node *outputs* in truth (shows physical deformation). |
| **Verdicts** | `COORDINATE DISTORTION` (display lies; geometry intact) · `SIGNAL DEFORMATION` (J is non-orthogonal; display honest) · `BOTH` · `CLEAN`, each with a magnitude bar. |
| **Enables** | Dual Align HONEST at this node (the scan reveals G). |
| **Tactical use** | Tells the two twin situations apart (§8, L4). Dual Align fixes lies, but it can't fix facts. |
| **Tradeoff** | A slower verdict than the Lens, and it can be spoofed. You may have to wait for, or create, rank-2 traffic, for example by letting a hostile through for one tick. |
| **Math analogue** | Testing whether `Jᵀ G_out J = G_in` (isometry) and whether `G_believed = G_true`. Two independent probes are needed to pin down a 2×2 symmetric form, which is why one component is never enough. |

### 6.4 Projection Pulse

| | |
|---|---|
| **Cost** | 2 BW. Installs a persistent filter on the node's output port and replaces any existing filter. |
| **Player input** | Mode, then **aim** `u`: click a component arrow or drag a direction. Axis-locked nodes allow only the local port axes. |
| **Modes** | **STRIP**: remove the part the readout detects, along `u`: `P = I − u rᵀ/(rᵀu)`. **KEEP**: pass only that part: `P = u rᵀ/(rᵀu)`. |
| **Readout used** | By default `r = G_believed · u` (the instrument converts the aim using what it believes the metric is). After Dual Align, `r` is honest or chosen independently. |
| **Correct use** | If the believed metric is true *and* the target is truly orthogonal to what you want to keep, STRIP removes the target exactly, with no friendly loss. |
| **Misuse consequences** | Under a lying metric, STRIP removes the target **plus a slice of the friendly signal it wrongly thinks overlaps the target**. That slice is pushed into the target's channel with **inverted sign** (§12). On a node with genuinely interfering components, an orthogonal STRIP leaves a residue. |
| **Tradeoff** | Cheap and decisive, and it's exactly as trustworthy as the node's instruments. |
| **Math analogue** | Projector built from a vector and a covector; orthogonal versus oblique projection. |

### 6.5 Backprop Strike

| | |
|---|---|
| **Cost** | 5 BW + 15 Heat. **Ping** mode: 1 BW, 0 damage, reveals the ripple only. |
| **Player input** | Launch node and readout. At the Core, pick its Threat or Supply readout. Elsewhere, aim (converted to a readout via the node's metric, so Dual Align matters here too). |
| **Sim** | A covector `g` travels the adjoint rail upstream, through each node: `g ← Jᵀ · Clip'ᵀ · Pᵀ · g`. Here `Clip'` is the Jacobian of the saturation clip at the node's current pre-clip vector: `(cap/‖x‖)(I − x̂x̂ᵀ)` when saturated, and `I` otherwise. At a fork (one node feeding many), the ripples arriving from each branch **sum**. At a join, the ripple **copies** into every incoming edge. Ripple speed is 0.5 s per node; the strike resolves within the tick. |
| **Damage** | Every emitter/threat host the ripple reaches takes `power × |g · d|`, where d is its emission direction and power = 1. **Friendly emitters are not exempt.** A friendly emitter with HP 3 loses output in proportion to the damage. |
| **Limits** | Packets already in flight still arrive. Saturated nodes and active clamps **deafen** the ripple (they scale it by `cap/‖x‖` and delete its radial component). A STRIP filter on the path removes the part of the ripple its readout covers (`Pᵀ`). |
| **Tactical use** | Kill an upstream source you can't reach or can't see clearly. Notice that **high-gain paths that make a threat dangerous also make your strike strong.** The ripple grows backward through the same amplifier that grew the threat forward. |
| **Tradeoff** | The most powerful tool in the game, and the most expensive. Its reach depends on the network being unsaturated *right now*, so timing matters (§12.2). |
| **Math analogue** | Reverse-mode differentiation / vector–Jacobian product, `g_prev = Jᵀ g`. |

### 6.6 Dual Align

| | |
|---|---|
| **Cost** | HONEST: 2 BW, and requires the node's metric to have been revealed this encounter (Lens or Scan). SPARE: 3 BW, no prerequisite. |
| **State changed** | Node `align`. It determines how readouts are built from aims for Pulses and Strikes launched at this node. Persistent until a Phantom re-corrupts the node. |
| **HONEST** | `r = G_true · u`. The aim becomes geometrically honest. |
| **SPARE (component c)** | `r` = the readout that **exactly ignores c** (its level lines run parallel to c). Pulses at this node then never touch c, whatever the metric. |
| **Shows** | The node's readout is redrawn as a grating, next to the aim arrow. On a lying or interfering node, the **arrow and the grating visibly disagree**. This is the game's central "aha" image. |
| **Limits** | In 2D, SPARE protects exactly one direction. A SPARE pulse is an **oblique projection**: anything you neither aimed at nor spared (noise, unknown white components) is amplified by up to `1/sin θ`, where θ is the true angle between the aim and the spared direction. When aim and spare are nearly parallel, SPARE amplifies noise into saturation. |
| **Tradeoff** | HONEST is cheap but needs knowledge. SPARE needs no knowledge but costs more and gets dangerous when components are nearly aligned. HONEST does **nothing** on a node whose display is already honest, so in a physical-deformation case it's wasted BW (§8, L4 twin). |
| **Math analogue** | The musical isomorphism `u ↦ G u` (raising and lowering indices); the annihilator of a vector; dual bases. |

### 6.7 Norm Clamp

| | |
|---|---|
| **Cost** | 2 BW. Persistent. |
| **Player input** | A ring on the node, sized in **true** units and snapping to 25/50/75/100% of `cap`. (On a lying display, the ring is drawn distorted. That is itself a clue.) |
| **Sim** | `x ← x · min(1, κ/‖x‖)`. It acts on the **whole packet**, so friendly components shrink in the same ratio as hostile ones. |
| **Benefits** | Prevents downstream saturation strain. Stops feedback loops from running away. Caps damage per tick. |
| **Costs** | Every tick the clamp is active, the lost friendly magnitude is logged as **clip loss** (it hurts Geometric Purity). The clamp also **deafens Backprop Strikes** passing through it, like a saturated node. |
| **Tradeoff** | It's the panic button. It always buys safety, it never removes the threat, and it costs signal you may need three nodes later. |
| **Math analogue** | Norm projection onto a ball, and the gradient attenuation of clipping/saturating activations. |

### 6.8 Chain Freeze

| | |
|---|---|
| **Cost** | Drains Freeze at 25 per real-time second (4 s from full). Recharges +5 per *unfrozen* tick. |
| **Effect** | Stops the combat clock. All tools stay usable. Perceive verbs that take a tick (Shear Scan) don't progress while frozen. |
| **Limits** | It can't be toggled faster than once per 0.5 s (no stutter-stepping). Insight score loses 2 points per frozen second after a 4 s free allowance per encounter. |
| **Tactical use** | Think through a hard propagation. Line up a strike in the gap before a saturation tick. |
| **Tradeoff** | It turns real time into turn-based play, at a cost. Experts freeze rarely and briefly. |
| **Math analogue** | None. It's a pacing tool, and honestly so. |

## 7. Enemy archetypes (exact behaviour)

Each archetype is a component attached to a node, an edge, or an emitter.
Behaviour runs in the tick's **threat phase** (§14.2).

### 7.1 Shear Phantom (representation attacker)
- **Attaches to:** a node. **HP:** none. It's purged instead (below).
- **Effect:** sets `display = S(k) = [[1,k],[0,1]]` (or a non-uniform stretch, in
  variants). The node's lattice is still drawn **square**, so the lie hides its
  own evidence. `G_believed` becomes `S(k)ᵀS(k)`. Physics is untouched.
- **Every 4 ticks:** re-shears with a new `k ∈ {−1.5, −1, −0.5, 0.5, 1, 1.5}`. Any
  Dual Align HONEST at the node is invalidated (SPARE survives, because it's
  metric-free).
- **Mk II:** forges a `CLEAN` verdict for a Shear Scan run on rank-1 traffic.
- **Purge:** a Shear Scan verdict of COORDINATE DISTORTION followed by Dual Align
  HONEST in the same or next tick. The Phantom is then gone for the encounter.
- **What it teaches:** the grid can lie, and a lie doesn't propagate.

### 7.2 Norm Spike (gain exploiter)
- **Attaches to:** an emitter. **HP:** 4.
- **Each tick:** strength `s ← 1.5 s`, capped at 8. Its direction `d` takes **one
  power-iteration step** toward the most-amplified direction of the downstream
  chain: `d ← normalise(Jcᵀ Jc d)`, where `Jc` is the product of Jacobians from
  its node to the Core (including installed filters).
- **Consequence:** over a few ticks, the spike finds and rides your network's
  highest-gain direction. **Its drift shows you where your network is most
  sensitive.**
- **Counter:** STRIP its direction upstream of the high-gain node (it re-seeks, but
  the filter changes `Jc`, so it may converge to a much weaker direction). Clamp
  the amplifier (safe, lossy). Or strike it: high gain makes your strike strong.
- **What it teaches:** sensitivity is directional.

### 7.3 Basis Worm (invariant tester)
- **Attaches to:** a node. **HP:** 2 (damaged when a pulse removes its component).
- **Each tick:** rotates the node's `frame` by +90°. That drags installed filters
  with it, because filters live in the frame. Its own component is drawn
  **without an arrow**: only a ring showing its *length* and a dashed arc showing
  its *angle to the friendly component*. Both are invariants.
- **Counter:** (a) Basis Rotate −90° each tick to cancel its spin (1 BW per tick:
  sustainable but draining). (b) Aim the pulse **relative to the friendly
  component** using the shown angle; the Pulse UI supports "aim at angle θ from
  component c". (c) Pulse in the one tick when its frame lines up with an
  axis-locked port.
- **What it teaches:** track invariants, not appearances.

### 7.4 Gradient Ghost (adjoint-visible saboteur)
- **Attaches to:** a node. **HP:** 3 (Backprop Strike only).
- **Effect:** modifies the node's Jacobian to `J' = J + a bᵀ`, with `b` chosen
  **orthogonal to all current traffic** (`bᵀ x = 0`). Forward packets are
  unchanged, so it's invisible to forward observation, Lens, and Scan.
- **Backward:** `J'ᵀ g = Jᵀ g + b (aᵀ g)`. Any Ping or Strike through this node
  **bends visibly**. The ripple leaves the node pointing somewhere the node glyph
  says it shouldn't.
- **Detonation:** when traffic at the node gains a component along `b` (for
  example, after the player rotates an upstream node's filter, or on a scripted
  traffic shift), the hidden term activates: `a (bᵀx)` is injected forward.
- **Counter:** Ping to find it (1 BW), then Strike *through* it. Damage to the
  ghost is `|aᵀ g|`, so choose a launch readout that lines up with `a`.
- **What it teaches:** some structure only shows when you look backward.

### 7.5 Interference Swarm (false independence)
- **Attaches to:** 3 hostile emitters at one node, each individually weak
  (strength 0.4).
- **Effect:** the node's display (or, in metric levels, its `G_true ≠ I`) is set so
  that each swarm member **looks perpendicular to the Core's Threat readout
  arrow** and therefore harmless. In truth, each one crosses the readout's level
  lines, and the three contributions add, up to `r(s₁+s₂+s₃) = 1.2` per tick
  when tuned to align.
- **The lie it exploits:** a readout *drawn as an arrow* via the believed metric.
  "Perpendicular to the arrow" is not the same as "ignored by the readout".
- **Counter:** Grating View, Lens, or Dual Align reveal that the members cross the
  level lines. Then one STRIP aimed at the swarm's **sum direction**, with a
  readout that SPAREs the friendly component, kills the whole swarm (they're 3
  vectors in 2D, so the part that matters is one-dimensional). Pulsing each member
  separately costs 6 BW and wastes time.
- **What it teaches:** a direction you point is not a direction you read. This is
  the duality reveal.

### 7.6 Jacobian Boss (chain-scale entity)
- A **subgraph**, not a unit: a set of nodes whose `J`s the boss rewrites on a
  schedule, plus a hidden **Heart** emitter. Exact behaviour is specified per boss
  (§9). General rules:
  - The Heart takes damage **only** from Backprop Strikes (the boss *is* the
    computation, so you hurt it through its sensitivities).
  - Each phase changes graph topology and/or local Jacobians at tick boundaries,
    telegraphed 1 tick ahead by a pulsing outline.
  - The boss never changes anything the player can't eventually observe.

## 8. Five level concepts (escalating)

### L1 — "Pressure Line" (propagation, sensitivity)
- **Graph:** Intake → A (stretch ×3 vertical) → B (inverter, −1) → C (stretch ×0.5) → Core.
- **Threat:** a hostile vertical trickle (0.4/tick). The Core's threat readout is
  vertical. Net gain is ×(−1.5), so the trickle arrives *inverted* and at 0.6.
- **Tools:** Projection Pulse, Norm Clamp.
- **The lesson:** a STRIP at Intake costs the same as one at C, but takes effect 3
  ticks sooner. A clamp at A stops saturation but trims friendly signal. The
  inverter means the red arrow at the Core points *down*. The first lesson is
  that sign is part of propagation.
- **Twist:** a second wave carries a horizontal friendly-only packet. Clamping A
  (an unnecessary clamp) shrinks it below the Core's Supply threshold three ticks
  later. **The consequence arrives somewhere else, later.**

### L2 — "Delta Fork" (multivariable chain rule, signed paths)
- **Graph:** Intake → Fork → {α: ×2 on hostile, ×0.5 friendly} and {β: ×−1.5
  hostile, ×0.5 friendly} → Join (sum) → Core.
- **Truth:** net hostile gain is `2 − 1.5 = 0.5`. Path β is *protecting* you.
- **Visible trap:** α's red arrow is huge, so the obvious move is to cut α. Then
  the Core receives β's −1.5 alone, triple the damage.
- **Correct plays:** STRIP on both paths (4 BW, clean), or Backprop Strike from
  the Core. Blame splits along both paths and recombines with the same signs:
  `2 − 1.5 = 0.5` damage per strike, weak. Players discover **"the cancellation
  that protects me also protects the source."**
- **Tools added:** ghost preview, Ping.

### L3 — "Turnstile" (safe transforms, representation vs geometry)
- **Graph:** 4 nodes, two of them **axis-locked** and rotated by 45°, and a Basis
  Worm on the middle node.
- **Goal:** STRIP a hostile that sits 45° off every available port.
- **Plays:** Basis Rotate the locked node to line up its port (1 BW, but this
  breaks the filter already installed there). Or aim relative to the friendly
  component on the Worm node. Or wait for the Worm's rotation to line its frame up
  with the port for one tick, and pulse then (free, but needs timing and Freeze).
- **The lesson:** rotation never changed a single length or angle, but it changed
  everything about which tool could reach what.

### L4 — "Leaning Relay" I and II (representation attack vs physical deformation)
- The worked puzzle (§10) and its **visual twin**. In I, a Phantom lies about N1.
  In II, N1 really shears the signal. **On first look, N1 is identical in both.**
- **Tell (free):** in I, the geometry at N2 contradicts N1 (a lie doesn't
  propagate). In II, N2 inherits N1's slant.
- **Tell (paid):** Shear Scan verdict.
- **What works in each:** HONEST alignment fixes I and does *nothing* in II
  (nothing to correct). SPARE fixes both. The naive pulse fails both, in
  different-looking ways (§12).
- Levels are served in random order, so the player has to diagnose, not memorise.

### L5 — "Undertow" (backward influence, duality, combined)
- **Graph:** 5 nodes with a fork. A Gradient Ghost sits on the fork node, an
  Interference Swarm at Intake, and a Shear Phantom on one branch.
- **Clues:** the Core's threat meter climbs, but no single red arrow is ever
  "pointed at" the threat readout. A Ping comes back bent at the fork.
- **Solution shape:** Ping to find the Ghost, Grating View to expose the Swarm,
  one SPARE pulse at Intake for the Swarm, and a Strike for the Ghost, launched
  *before* the Phantom's branch saturates and deafens it.
- **The lesson:** forward, backward, coordinates, and metric all coexist, and the
  order you resolve them in matters.

## 9. Jacobian Boss: THE CARTOGRAPHER

> *"It does not attack the network. It redraws the map the network uses to know
> itself."*

**Arena:** 8 nodes. Friendly Intake, the hidden Heart, a Fork, paths α/β, a Join, a
Mixer M, and the Core. Heart HP: 4 (Phase 1) + 4 (Phase 2) + 8 (Phase 3).
Combat tick: 4 s, dropping to 3 s in Phase 3.

### Phase 1 — "Two Rivers" (learn its paths)
- **Graph:** Heart & Intake → Fork → α `diag(2, 0.5)` and β `diag(−1.5, 0.5)` → Join → Core.
  Hostile is horizontal (e₁), friendly vertical (e₂). The Core's threat readout is e₁.
- **Forward:** hostile net gain is +0.5, friendly net 1.0. Damage starts low.
- **Boss action:** every 3 ticks, **"erosion"** moves β's hostile gain 0.5 toward 0
  (−1.5 → −1.0 → −0.5 → 0). The net forward gain climbs 0.5 → 1.0 → 1.5 → 2.0.
  The boss is breaking its own disguise in order to hurt you.
- **The decision:** strike damage at the Heart equals the *same* net gain (blame
  flows along the same signed paths as harm). Early strikes are weak (0.5). Late
  ones are strong (2.0), but by then you're taking 2.0 per unit of Heart strength
  per tick.
  - *Option A, the patient duelist:* clamp the Join to cap damage, wait for
    erosion, then strike at full gain. The clamp deafens strikes passing through
    the Join, so **remove it before striking**.
  - *Option B, forcing the blame:* STRIP the hostile on β early. The net gain
    jumps to 2.0 at once, so you take damage immediately, but every strike now
    lands at 2.0. Two strikes clear the phase.
  - *Trap:* STRIP α (the loud one). The net becomes −1.5 and the strike deals 1.5.
    That's workable, but you also lose α's friendly contribution if you misaim. A
    common, recoverable mistake.
- **Exit:** Heart P1 HP reaches 0.

### Phase 2 — "The Loop" (feedback)
- **Boss action:** adds an edge Join → Fork whose Jacobian is chosen so that the
  loop's **round-trip map** (Fork → paths → Join → back to Fork) is
  `R = [[0.6, 0.9],[0.9, 0.6]]`. Its eigen-gains are **1.5** along `(1,1)/√2`
  (runaway) and **−0.3** along `(1,−1)/√2` (decays, flipping sign each lap). Friendly and hostile both
  circulate. Anything with a `(1,1)` component grows ×1.5 per lap.
- **Norm Spike spawns** inside the loop and power-iterates to `(1,1)/√2`. Its
  drift is a free, live signpost to the loop's dangerous mode.
- **The decision:** you can't strike the Heart while the loop is live. Its ripple
  goes around forever and the game declares the strike absorbed.
  - **Clamp the loop** (anywhere on it): safe, but the boss counts a clamped loop
    as still live, so the phase doesn't end and clip loss piles up.
  - **STRIP the runaway mode** at one loop node, aimed along `(1,1)/√2` and
    SPAREing the friendly component. The loop's gain drops below 1. After 3 ticks
    the loop collapses and the edge breaks.
  - The pulse readout matters here: under the arena's honest metric, the dangerous
    mode and friendly e₂ are 45° apart, so a SPARE pulse amplifies noise by at
    most √2. That's tolerable.
- **Exit:** loop gain < 1 (computed with filters, ignoring clamps) for 3
  consecutive ticks. The Heart is then exposed. Erosion has finished by now, so the
  forward path gain is 2.0 and two strikes clear Phase 2's 4 HP.

### Phase 3 — "False North" (duality and transpose under a lying map)
- **Boss action:** the Heart retreats upstream behind the **Mixer**
  `M = [[1, 0],[2, 1]]` (a *physical* shear: it funnels horizontal into vertical),
  and a **Decoy** emitter appears next to it. A **Shear Phantom** lies about the
  Mixer's display. The Core's alarm readout becomes `r = e₂` (vertical).
- **Truth:** blame at the sources is `Mᵀ r = (2, 1)`. The Heart emits horizontally
  (e₁) and gets blame **2**. The Decoy emits vertically (e₂) and gets blame **1**.
- **The trap (the inverse instinct):** "The alarm reads vertical. Undo the mixer
  and see which input moves the output vertically." That gives `M⁻¹ e₂ = e₂`, which
  points at the Decoy. That's the *vector* rule (where would I need to push?). The
  question is "who is the Core sensitive to?", and that needs the *readout* rule
  (`Mᵀ`).
- **Mechanics:** forward pulses damage only the Decoy, and the Decoy regenerates 1
  HP per tick. The Heart takes Strike damage only. A Ping shows the ripple
  arriving at the source plane as a **grating** tilted toward the Heart. On the
  Phantom's lying display it *looks* tilted toward the Decoy, unless the player
  uses Grating View or Dual Align HONEST.
- **Boss action, "Flip the Map":** every 4 ticks the boss **transposes** the
  Mixer (`M ↔ Mᵀ`). With the mixer now `Mᵀ = [[1,2],[0,1]]`, blame is
  `(Mᵀ)ᵀ r = M r = (0, 1)`. The Heart gets blame **0** and the Decoy **1**. **Striking
  right after a flip is wasted.** Players must re-Ping after each flip, or better,
  notice the flip glyph and time strikes in the pre-flip window, using Freeze.
- **Exit:** Heart HP reaches 0. **Mastery feeling:** by now the player predicts the
  Cartographer's next map before it redraws it.

### Why this boss works
Every phase is the *same* skill (reading propagation) at a higher level:
signed path sums → loop eigen-gain → transpose under coordinate lies. The boss
never adds HP for its own sake; it adds **structure**.

## 10. Fully worked puzzle: *Leaning Relay* (L4-I)

### 10.1 Starting network

```
 [N0 INTAKE] ──▶ [N1 RELAY] ──▶ [N2 BOOSTER] ──▶ [N3 CORE]
  friendly F       sealed          J = diag(1,3)     Supply r_S = (1,0) ≥ 1.8
  Leech L          (truth: J = I)   cap = 6            Threat r_T = (0,1) ≤ 0.5
                   Phantom: S(1)    output port only   integrity 12
                   output port                         win: 6 clean ticks in a row
```

- **Clock:** 4 s per tick. Wave *w* is emitted at tick *w*, sits at N1 on *w+1*,
  N2 on *w+2*, and reaches the Core on *w+3*.
- **Emitters at N0:** friendly `F = (2, 0)` constant (HP 3). Hostile **Leech**,
  direction `(0, 1)`, strength `c_w = min(2, 1 + 0.5w)` (HP 3).
- **Damage:** per tick, `max(0, |r_T(x)| − 0.5)` to Core integrity.
- **Resources:** BW 10 (+1/tick), Heat 0, Freeze 100.
- **Tools:** Projection Pulse, Dual Align, Shear Scan, Metric Lens, Backprop
  Strike, Norm Clamp, Chain Freeze.

### 10.2 Hidden truth

- N1's real transform is the identity (a relay). A **Shear Phantom** sets its
  display to `A = [[1,1],[0,1]]` and draws the lattice square anyway.
- So N1 shows `F' = A F = (2, 0)` and `L' = A·(0,c) = (c, c)`. The hostile arrow
  appears at **45°** to the friendly one. In truth they are **perpendicular**
  (`F·L = 0`, while the display's `F'·L' = 2c`).
- N1's believed metric (in true coordinates) is `AᵀA = [[1,1],[1,2]]`.

### 10.3 Visible clues (free)

1. N1 shows red leaning 45° toward cyan, as if they interfere.
2. **N2 shows red exactly vertical and cyan exactly horizontal, perpendicular.**
   N2's glyph is an honest vertical stretch, and a vertical stretch *can't* turn
   a 45° pair into a 90° pair while keeping cyan horizontal. So either N1's
   transform does something odd, or **N1's display is lying.**
3. N1 is sealed (its transform is hidden), so the clue is suggestive, not
   conclusive. Expert players commit on clue 2. Cautious players scan.
4. The Core threat meter starts climbing at t3; the Leech grows every tick until
   t2.

### 10.4 Threat behaviour and propagation order (no player action)

From the verification script (`S0 no action`):

The player has **3 ticks (12 s)** before first damage and about 6 ticks before

## 11. Valid solutions (at least two, here five)

All verified by the script. "Cost" includes the minimum resources used.

### Solution A — Diagnose, then align honestly (the "careful" line)
1. t0: **Shear Scan** N1 (25 Heat). Traffic is rank 2 (cyan and red non-parallel),
   so the scan is valid.
2. t1: verdict `COORDINATE DISTORTION`. **Dual Align HONEST** N1 (2 BW). The
   Phantom is purged.
3. t1: **Projection Pulse STRIP** at N1, aimed at red (2 BW). Readout `r = G_true u = (0,1)`.
4. **Result:** Core `(2, 0)` from t3. Win at t8, Core HP 12. Cost: 4 BW, 25 Heat.

### Solution B — Don't trust the grid, spare the friendly (the "insight" line)
1. t0: **Dual Align SPARE (cyan)** at N1 (3 BW). The readout's level lines now
   run parallel to cyan. The player *sees* the aim arrow (45°) and the grating
   (horizontal lines) disagree, which is the duality image.
2. t0: **Pulse STRIP** aimed at red (2 BW).
3. **Result:** identical to A (Core `(2,0)`, win t8, HP 12). Cost: 5 BW, **0 Heat**,
   top Insight bonus. (In the physical twin, this same line also wins.)

### Solution C — Reach back (the "chain rule" line)
1. t1: **Backprop Strike** from the Core's Threat readout (5 BW, 15 Heat).
   Ripple: `g = (0,1)` → back through N2: `diag(1,3)ᵀ g = (0,3)` → N1 (`J = I`):
   `(0,3)` → at Intake: Leech damage `|g·(0,1)| = 3`, which is lethal; friendly
   damage `|g·(1,0)| = 0`.
2. **Result:** the Leech dies at t1. Wave 0 was already in flight, so t3 still
   takes 2.5 damage. Clean from t4. Win at t9, Core HP 9.5.
3. **Upgrade C+:** also put a plain STRIP at N2's output (honest frame, 2 BW) to
   catch the in-flight wave. Win at t8, HP 12.
4. **Lesson:** the ×3 Booster that made the Leech dangerous is the same ×3 that
   made the strike lethal. A strike launched from N1 instead would carry only
   `(0,1)` and deal 1 damage.

### Solution D — Fix it downstream (the "brute but valid" line)
1. t1: **STRIP** at N2's output (2 BW). N2's display is honest, so the naive aim is correct.
2. **Result:** clean from t3. But from t5 the Leech is at full strength, N2
   **saturates before the filter** (clip, then filter), and friendly arrives at
   **1.90 instead of 2.00**. Win at t8, Core HP 12, **N2 integrity 8 → 4**,
   Purity ≈ 95%.
3. **Lesson:** valid, cheap, and lower-ranked. It treats the symptom after the
   amplifier has already done damage.

### Not a solution — Norm Clamp at N1 (cap 2.2)
Shrinks friendly together with hostile. Supply falls to 1.56 and the threat still
arrives at 4.67. **LOSS at t6.** This is the canonical "power without understanding"
move.

## 12. A failed intervention, propagating

### 12.1 The naive pulse (most players' first try)

**Action:** at t1, the player STRIPs at N1, aiming at the red arrow *as
displayed* (45°). The node turns the aim into a readout with its believed metric
`AᵀA`.

**What the simulation does** (true coordinates):

- Packet at N1: `x = (2, c)`. Aim `u = (0,1)`. Believed readout `r = AᵀA·u = (1, 2)`.
- STRIP: `x − u·(r·x)/(r·u) = (2, c) − (0,1)·(2 + 2c)/2 = (2, −1)`, **independent of c.**
- The hostile is fully gone, **plus one unit of friendly, pushed into the vertical
  channel with inverted sign.**
- N2 (×3 vertical): `(2, −3)`. Core: Supply 2.00 ✓, Threat |−3| = 3.00 ✗, 2.5
  damage every tick. **LOSS at t7.**

**What the player watches:**

| Tick | Screen |
|---|---|
| t1 | The pulse fires at N1. **The red arrow vanishes.** Relief. But the cyan arrow at N1 *tilts downward*. |
| t2 | That tilted cyan packet reaches N2. The Booster triples its vertical part, and the cyan arrow now points steeply **down**. |
| t3 | The Core's threat meter fires **again**. No red anywhere. The Ledger reads: `t3 THREAT 3.00 — source: friendly (inverted)`. |
| t4+ | Steady burn. The threat bar is **mirrored**: it fills downward, a polarity the player hasn't seen before. |

**Why it's understandable:** the player removed red and then saw *cyan* bend.
The bend appears at exactly the node where the pulse fired, and it grows at exactly
the node that grows vertical things. The fix becomes the question "why did my pulse
think cyan was partly red?", which leads straight to "the grid lied about the angle."

**Recovery (still winnable):** at t3, when the Core fires, the player re-pulses
with SPARE (the new filter replaces the old one). Wave 1 is already past N1, so t4
still burns. From t5 the Core is clean, and the player wins at t10 with HP 7.0: a
lower rank, and a lesson learned through a consequence rather than a lecture. A
player who reads the cyan bend at N1 and re-pulses at **t2** loses only one tick
(HP 9.5, win at t9). Reading propagation early pays off.
*(Verified: `RECOVERY` scenario in the script.)*

### 12.2 The expert-tier failure: the late strike

**Action:** the player waits until t4 to Backprop Strike from the Core.

- At t4, N2 holds wave 2 at full strength: pre-clip `(2, 6)`, `‖·‖ = 6.32 > 6`, so it's **saturated**.
- Backward through the clip: `Clip'ᵀ g = 0.949·(I − x̂x̂ᵀ)(0,1) = (−0.28, 0.09)`.
  Then through `diag(1,3)ᵀ`: `(−0.28, 0.28)`.
- The Leech takes **0.28** (not 3). The **friendly emitter takes 0.28** too, and its output drops ~9%.
- **LOSS at t6**, with Supply sagging to 1.73.

**What the player watches:** the magenta ripple hits N2 and **shrinks and
bends sideways**. It reaches Intake weak and splits between both emitters. The
cyan source flickers. The lesson: *a saturated node is deaf to blame*, so strike
before the amplifier is full.

### 12.3 The same situation, for a player who has never studied linear algebra or calculus

> You're guarding a pipe of four rooms. Cyan light goes in one end and has to
> reach the Core. A red parasite rides along with it.
>
> The second room is a big amplifier: anything **vertical** comes out three
> times bigger. So the red, which travels vertically, gets scary fast.
>
> The first room has a screen. On it, the red and the cyan look like they're
> leaning into each other, maybe tangled. But in the very next room the red is
> straight up and the cyan is flat, cleanly separate. Rooms are supposed to be
> honest, so one of them is lying. And the amplifier can't straighten things out
> like that.
>
> If you fire your filter at the red using the first room's screen, the red
> disappears… and the cyan bends downward. One room later it's bent three times
> worse, and the Core is still burning, from your *own* light. Your filter

>
> Better options: tell the filter *"whatever you do, don't touch cyan"*. Or

No numbers, no words like "metric" or "transpose". Just *the screen lied*,
*the lie didn't travel*, *my filter believed the lie*, and *blame grows back
through the same amplifier that harm grew through*.

## 14. Combat clock / real-time system

### 14.1 Cadence
- A **tick** is the atomic simulation step. The base period is 4.0 s; harder
  levels go down to 2.5 s.
- The player can act at any time between ticks. Actions **queue** and resolve at
  the next tick boundary, in input order, with the queue shown as icons on the
  clock ring. Exceptions: **Freeze** and **Perceive results already paid for**
  (Lens draws instantly).
- The clock ring fills, pulses at 75%, and chimes at the boundary. It's readable
  without looking at numbers.

### 14.2 Tick resolution order (deterministic)
1. **Player queue:** apply installs, alignments, rotations, and strikes. Strikes
   resolve against the *current* state, including what N2 holds right now.
2. **Threat phase:** Phantoms re-shear on schedule, Worms rotate, Spikes
   power-step, the boss rewrites.
3. **Emit:** emitters add their packets at their nodes.
4. **Advance:** every packet moves one edge. Nodes process arrivals in topological
   order: `J → clip → clamp → filter`. Joins sum.
5. **Core:** apply readouts; damage, supply check, streak update.
6. **Upkeep:** saturated nodes lose integrity, BW +1, Heat −10, Freeze +5 (if not
   frozen); the Ledger is written.
7. **Win/lose check.**

### 14.3 Pressure without APM
- The design target is **≤ 2 meaningful actions per tick** at par. Puzzles are
  authored so no par solution needs more than 3 actions in a single tick.
- **Asynchronous chains** (late game): two subgraphs with periods of 4 s and 3 s,
  synchronising every 12 s. Sync ticks are marked on both clocks and are the
  natural moments to strike.
- **Clock-off mode** (accessibility and prototype A/B): ticks advance only on
  player command. Scoring is unchanged except for the Freeze penalty.

## 15. Progression system

Progression unlocks **ways of seeing**, not stronger numbers.

| Watch (act) | Concept phase | Tools unlocked | HUD upgrades |
|---|---|---|---|
| I — Pressure | 1–2 Propagation, Sensitivity | Pulse, Clamp, Freeze | Ghost preview (depth 1) |
| II — Turnstile | 3 Safe transforms, 4 Interference | Basis Rotate, Ping | Ghost depth 2, angle arcs |

| V — Cartographer | 8 Combined chains | — | Debug view (optional) |

- **Codex ("Field Notes"):** each entry unlocks *after* the player has done the
  thing, named first in game terms and then in maths terms. Example: *"Blame
  Grows Backward. You struck through the Booster and the ripple tripled. Engineers
  call this a vector–Jacobian product; the rule is `g ← Jᵀg`."* This is the

- **Mastery medals per level:** Pure (≥98% Purity), Blind (no Perceive verbs),
  Still (no Freeze), Lever (Chain Elegance S). These reward replaying with a
  different solution family.
- **Mirror levels:** after Watch III, earlier levels come back with a Phantom
  added. The same graph now needs the new way of seeing.
- **No permanent stat upgrades.** BW, Heat, and Freeze caps are per-level design

## 16. Scoring system

Each category scores 0–100. The level rank (S/A/B/C) uses the weighted mean
shown. "Par" values come from the solver (§19.3).

| Category | Weight | Formula |
|---|---|---|
| **Threat Suppression** | 25% | `100 · (1 − Σ_t threat_t / Σ_t threat_t^noAction)` over the encounter |
| **Geometric Purity** | 20% | Mean over Core ticks of `100 · max(0, 1 − ‖y_t − y*_t‖ / ‖y*_t‖)`, where `y*` is the friendly-only Core vector with no interventions and no threats |
| **Norm Stability** | 15% | `100 − 10·(saturated node-ticks) − 5·(clamp-active ticks)`, floored at 0 |
| **Chain Elegance** | 15% | **Leverage** = Σ over interventions of (hostile magnitude prevented, summed over every downstream node it would have passed) / BW spent, normalised to par. Upstream fixes score higher automatically. |
| **Intervention Efficiency** | 10% | `100 · min(1, par_actions / actions)`. Replacing a filter counts as an action. |
| **Insight Bonus** | 15% | `100 − Heat_spent/2 − 15·previews − 2·(frozen s beyond 4)`, floored at 0 |

**Leaning Relay under this rubric (approximate):**
- A: Suppression 100, Purity 100, Stability 100, Elegance high, Insight ~87 → **S−/A+**
- B: same, Insight 100, −1 action vs A → **S**
- C+: Suppression 100, Purity 100, Elegance highest, Insight ~92, 7 BW → **S**
- D: Purity ~97, Stability 60 (4 saturated ticks), Elegance low → **B**

So several families can reach top rank, by different routes.

Rule: **every concept is introduced by a consequence first, and named only in the
Codex afterwards.**

## 19. Difficulty-generation variables and procedural generation

### 19.1 Variables

| Variable | Range | Effect on difficulty |
|---|---|---|
| Depth (nodes on the critical path) | 3–8 | Longer latency to read consequences; more leverage choices |
| Branching (forks/joins) | 0–3 | Signed path sums |
| Gain spread (max singular value per node) | 1–4 | Saturation pressure; strike strength |
| Non-normality (‖JᵀJ − JJᵀ‖) | 0–4 | How much transpose differs from the "obvious" reverse |
| Display distortion k | 0–1.5 | Size of the angle lie |
| Physical deformation fraction | 0–1 | Probability a slanted node is real rather than a lie |
| Near-parallelism (min true angle between components) | 90°–15° | SPARE noise amplification |
| Hidden fields | 0–4 | Inference load |
| Tick period | 4.0–2.5 s | Time pressure |
| Threat growth | ×1–×1.5 per tick | Window before collapse |
| Concurrent threat types | 1–3 | Prioritisation |
| Resource slack (budget / par cost) | 2.0–1.1 | How much brute force is affordable |
| Spoof probability (Mk II) | 0–0.5 | Distrust of diagnostics |

### 19.2 Generation pipeline (semi-procedural)

1. **Choose a concept target** (e.g. "representation vs physical", "signed paths").
   This picks a **motif library**: chain, diamond (fork/join), loop, shear-relay,
   ghost-fork.
2. **Assemble** 1–3 motifs into a graph, respecting a depth/branching budget.
3. **Assign Jacobians** from a typed palette (rotation, axis stretch, shear,
   inverter, mixer), constrained so friendly reaches the Core above Supply when
   there are no threats.
4. **Place threats** that match the concept target, and pick hidden fields.
5. **Solve** (below). Reject, or tune numbers and repeat.
6. **Polish pass** (human): layout, ledger flavour, and naming.

### 19.3 Solvability and quality checks (the solver)

The simulation is deterministic and small, so a **headless solver** can search it:

- **Action abstraction:** `{tool, node, mode, aim ∈ (visible components ∪ port
  axes ∪ 15° grid), tick ∈ [0, horizon]}`. Typically fewer than 2,000 actions per
  tick. Beam search (width ~500) over ≤ 4 actions, with ties broken by score.
- **Required checks for a generated puzzle to ship:**
  1. **Solvable:** at least one action sequence wins within the resource budget.
  2. **Concept-gated:** a **naive-policy bot** loses. This bot trusts displays,
     always aims at red, never uses Perceive verbs, and clamps when HP < 50%. If
     the naive bot wins, the puzzle doesn't test its concept.
  3. **Plural:** at least 2 **solution families** win, where a family is the
     unordered set of `{tool, node}` pairs. Ideally one diagnostic family and one
     insight family.
  4. **Not degenerate:** no single action wins alone at S rank (unless it's a
     tutorial).
  5. **Readable failures:** for the 3 most common losing first actions, the first
     Core damage they cause must come **≥ 2 ticks after** the action, so the player
     can watch it travel.
- **Par** = the cheapest winning sequence found (actions, BW). Rank thresholds
  follow from par.
- The solver also produces **hint data**: the first divergence between the naive
  bot's trace and a winning trace, i.e. the node where the naive reading goes
  wrong.

## 20. Browser prototype architecture

**Stack:** TypeScript, Vite, Canvas 2D, Vitest. No engine and no physics library.
2×2 maths is written by hand (about 100 lines).

```
src/
  math/        vec2.ts, mat2.ts           pure functions; inverse, transpose, clip Jacobian
  sim/
    encounter.ts                          load JSON → runtime state
    tick.ts                               §14.2 resolution order (pure: state, actions → state, events)
    node.ts                               J → clip → clamp → filter
    adjoint.ts                            Backprop Strike / Ping (vector–Jacobian products)
    threats/                              one file per archetype; each exports onThreatPhase(state)
    tools/                                one file per tool; validate(state, action) + apply(state, action)
    score.ts                              §16
  view/
    renderer.ts                           Canvas: graph, rails, packets, ripples
    nodeChamber.ts                        local lattice, arrows, gratings, ellipses (display transform)
    hud.ts, inspector.ts, ledger.ts
  input/       hotkeys.ts, aiming.ts      aim capture, relative-angle aiming
  app/         clock.ts, game.ts          real-time loop; queues actions; calls sim.tick
  levels/      *.json                     schema §18
  solver/      search.ts, naiveBot.ts     headless; runs in Node for CI and level checks
tests/
  invariants.test.ts                      rotation preserves dot; r' = A⁻ᵀr preserves readings; strike = finite-difference sensitivity
  levels.test.ts                          every level: solvable, naive bot loses, ≥2 families
```

**Principles**
- **The sim is pure and deterministic:** `tick(state, actions) → { state, events }`.
  The renderer reads only from state and events. This lets the same code run
  the game, the solver, tests, and replays.
- **Everything is in true coordinates internally.** Display transforms exist
  only in `view/`. That makes it structurally impossible to mix up truth and
  display.
- **Replays are action logs** `[tick, action]`. They're tiny, shareable, and exactly
  what playtest telemetry needs.
- **Property tests guard coherence:** e.g. Backprop Strike damage at an emitter
  must equal the finite-difference sensitivity `∂(r·y_core)/∂s` along the
  emitter's direction, to within ε, on random unsaturated graphs. If maths and game
  ever disagree, CI fails.
- `scripts/verify-leaning-relay.mjs` in this repo is the seed of `sim/` and should
  be absorbed into it.

## 21. Smallest viable vertical slice

**Question it must answer:** *Is predicting and manipulating propagation through a
corrupted chain actually fun?*

**Contents (target: 2–3 weeks for one developer):**
- **3 encounters:** T2 *Lever* (propagation, 5 min), L4-I *Leaning Relay*, L4-II
  *Leaning Relay (physical twin)*. The two L4 variants are served in random order.
- **5 tools:** Projection Pulse, Dual Align (HONEST + SPARE), Shear Scan, Backprop
  Strike, Chain Freeze. (Cut: Lens, Rotate, Clamp. The Clamp is kept only as the
  tempting wrong answer, if time allows.)
- **No** progression, narrative, procedural generation, bosses, audio polish, or
  particles. Flat shapes on Canvas, a ledger, and one clock.
- **Clock toggle:** real-time (4 s) vs turn-based, randomised per tester for A/B.
- **Built-in prediction prompts** (playtest build only): before each action resolves,
  ask *"Where will the Core's arrow point in 3 ticks?"* with 4 options. This is a
  free, direct measure of whether players are building a model.

**Success criteria (6–10 testers, think-aloud):**
1. **Prediction accuracy rises** from the first to the third encounter (target:
   chance → above 60%).
2. **Unprompted causal language:** testers say things like "the screen is lying"
   or "it's coming from upstream" without being taught the words.
3. **Twin discrimination:** on the second twin, at least half of testers use the
   N2-disagreement clue or a Scan *before* acting.
4. **Voluntary replay:** at least 40% replay a solved encounter to try a different
   solution.
5. **Failure readability:** after the naive-pulse failure, testers can explain
   *why* it failed within 30 s of watching it.

If 1 and 5 fail, the core grammar isn't readable, so fix visuals before adding
content. If 1 and 5 pass but 4 fails, the puzzle is understandable but not
compelling, so revisit plurality and scoring. If the turn-based arm is clearly
preferred, the real-time layer is a separate question; drop it from the slice.

## 22. Premortem

*It's 18 months from now and NULLBASIS failed. Why?*

### 22.1 The three largest gameplay-design risks

1. **Readability collapse.** Each node shows a lattice, 2–4 arrows, a grating, a
   ring, glyphs, and two rails. Players stop *seeing* and start *guessing*, and
   the game becomes trial-and-error with a pretty clock. **Leading indicator:**
   prediction-prompt accuracy stays at chance. **Mitigations:** 2D only; at most 3
   components per node before Act IV; hard caps on simultaneous overlays; the
   Inspector carries detail so the graph doesn't have to; every hidden field must
   leave a free footprint (§4.3).
2. **Dominant strategies erase the concepts.** SPARE pulses are metric-free, so a
   player who learns "always SPARE the cyan" can bypass the whole metric act.
   Backprop Strike can likewise become a universal answer. **Mitigations (already
   in the design, and they must be tuned seriously):** SPARE costs more and
   amplifies unaccounted components by 1/sin θ (white/noise components appear from
   Act III onward); saturation and clamps deafen strikes; packets in flight make
   strikes slow to pay off; the solver's "≥ 2 families" check plus the naive-bot
   check catch levels where one trick dominates. **Honest note:** if SPARE stays
   dominant, the right response may be to let it be the "expert's shortcut" and
   move the metric lesson onto *length* questions (clip radii and clamp rings are
   metric-dependent, and SPARE doesn't help with them).
3. **The real-time layer fights the reasoning layer.** Thinking about
   transposes under a 4-second clock may feel like a math test with a timer. Or
   Freeze gets used constantly, so the game becomes turn-based with extra steps.
   **Mitigations:** slow clock, generous latency (consequences take ≥ 2 ticks),
   clock-off mode, and the A/B in the slice. Be ready to ship a mostly turn-based
   game with real-time *pressure events* if that's what the data says.

### 22.2 Mathematical concepts that don't translate naturally into fun

- **Annihilation is metric-free.** "Remove this component without touching that
  one" never needs a metric. Only questions about **length, angle,
  orthogonality, and "closest"** do. Puzzles that claim to be about metrics but are
  really about annihilation will feel arbitrary to sharp players. Author metric
  puzzles around clip radii, clamp rings, orthogonal (single-click) pulses, and
  noise amplification.
- **Transpose (backprop) vs inverse-transpose (re-expressing a readout).** These
  are the *same* operation (pullback) seen from two directions. The brief's
  requirement to "distinguish transpose from inverse-transpose" is mathematically
  real but not a natural player distinction. Recommendation: don't make players
  tell those two apart. Make them tell **the vector rule (push / undo, `A`, `M⁻¹`)**
  from **the readout rule (blame / read, `Aᵀ`, `A⁻ᵀ`)**. The Cartographer's Phase 3
  does exactly this.
- **Normalisation layers** (LayerNorm-style divide-by-norm) are nonlinear and
  direction-only. They create beautiful puzzles on paper and opaque ones on screen.
  Leave them out of the base game; the radial clip covers the norm drama.
- **Higher dimensions, curvature, and second derivatives:** no. They don't fit
  the 2D readability budget.
- **Covectors as a *word*:** never used in play. They exist only as gratings and
  in the Codex.

### 22.3 Mechanics to simplify or remove

- **Merge Metric Lens and Shear Scan** into one "Survey" with two read modes, if
  playtests show players can't articulate the difference. (Keep them separate in
  the slice, since that's part of the test.)
- **KEEP mode** may be redundant with STRIP plus SPARE. Cut it unless a level
  needs it.
- **Basis Rotate** has low standalone value (it's pure representation). Keep it
  only in axis-locked and Worm levels. It may become a property of ports instead of
  a tool.
- **Asynchronous clocks:** a late-game spice. Don't build them until real time is
  validated.
- **Boss Phase 2 eigen-modes:** keep the loop, but the player-facing rule should be
  "the Spike shows you the runaway direction". The eigenvalue framing stays in
  Debug.
- **Friendly-fire from strikes:** keep (it's a great consequence), but show it
  loudly or it will read as a bug.

### 22.4 The single experiment to prototype first

**The Twin Relay test.** Build *Leaning Relay I* and *II* only: one 4-node chain,
the naive Pulse, Dual Align (HONEST/SPARE), Shear Scan, a turn-based clock, and the
prediction prompt. Serve the twins in random order to 6–10 people who have never
studied linear algebra.

It tests, in one sitting, the three claims this whole design rests on:
- **Propagation is legible:** can they predict the bend after the naive pulse?
- **"The grid can lie" is discoverable and satisfying:** do they find the
  N2-disagreement clue, and does finding it feel like a win?
- **Move-vs-read is intuitive in action:** does the arrow/grating split on SPARE
  produce an "oh" moment?

If that sitting produces think-aloud lines like *"wait, the screen's wrong, not
the signal"*, build the rest of the game. If it doesn't, no amount of bosses
will fix it. It takes about one week, and the maths is already verified in
`scripts/verify-leaning-relay.mjs`.
